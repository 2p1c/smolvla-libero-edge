# 一天打通：SmolVLA × LIBERO 微调 → 仿真评测 → 部署优化

目标岗位：VLA 微调部署 / 机器人数据工程。所以这一天的重心是：**数据 30% · 评测与部署 50% · 模型 20%**。
模型结构不改，只用 LeRobot 的标准微调；你的差异化在“数据看得清、评测测得准、部署算得明白”。

## 0. 先想清楚：简历上要出现哪几个数

| # | 数字 | 来自哪个任务 | 说明 |
|---|---|---|---|
| A | 微调前 → 微调后成功率 | T3 + T6 | “前”= 早期 checkpoint（2.5k 步）和训练曲线，见下方说明 |
| B | 训练曲线 2.5k / 5k / 10k / 20k 步的成功率 | T6 | 证明你会看收敛，而不是只报最后一个数 |

| D | 推理延迟 FP32 → BF16 → 5 步去噪的加速比，且成功率不掉 | T8 | 部署岗最爱问的数 |

**关于“微调前”**：`smolvla_base` 是在 SO100 机械臂数据上预训练的，动作维度、相机名、归一化统计量都和 LIBERO 不一样，直接拿去 LIBERO 跑多半会报维度错误或成功率约为 0。这本身是个面试考点：**换了机器人本体，“零样本基线”往往没法定义。** 所以：

- 花 5 分钟试一次 `smolvla_base` 零样本（T3），报错或 0% 都如实记下来，再写清楚原因；
- 真正有信息量的“前后对比”用 **2.5k 步 checkpoint → 20k 步 checkpoint** 的曲线，加上和官方 checkpoint 的对比。

## 1. 时间表（一张 GPU，约 11 小时）

推荐租 **A100 40/80GB**，或者 **4090 24GB**（显存紧，训练时 BATCH=16）。核心原则：**训练是最长的那根杆，越早启动越好，其余事情都塞到训练期间做。**

```
时间    GPU 上在跑                     你在做
0:00 ── T1 环境 + 冒烟测试 ─────────── 量 it/s、s/episode，重算预算
1:00 ── T4 正式训练（tmux，后台）──┬── T2 数据审计（CPU）
        同时：T3 官方模型基线评测   │   T3 base 零样本试一次
        同时：T7 官方模型 n 消融    │
4:00 ── 训练继续 ──────────────────┼── 出了 5k/10k checkpoint 就边训边评（T6）
5:30 ── 训练结束 ──────────────────┘
5:30 ── T6 评测 20k checkpoint（10 回合/任务）
6:30 ── T8 延迟测试（GPU 必须空闲！）
7:00 ── T7 在微调模型上补测最佳 n、T8 5 步去噪的闭环成功率
8:30 ── T5（选做）数据配比训练 + 评测
10:00 ─ T9 出图、GIF、失败分析、填 README、写简历条目
```

> 如果 T1 量出来 it/s 太低（20k 步要超过 4 小时），就把 STEPS 降到 10k、放弃 T5。**用实测数据重做预算**，这是本项目第一个可复用技能。

**检查点问题**：

### T2 数据审计（训练期间，CPU，约 1.5 小时）★ 数据工程岗重点

**目标**：在训练前/训练中搞清楚喂给模型的到底是什么数据。写一个 `scripts/audit_dataset.py`，输出 `results/data_audit.json` 和几张图。

至少回答这些问题：

| 审计项 | 怎么算 | 为什么重要 |
|---|---|---|
| 每个 suite / 每个 task 的回合数 | 按 `task_index` 分组 | 训练用的是 4 个 suite 混合数据，评测只测 spatial，配比直接影响结果 |
| 回合长度分布 | 每回合帧数的 min / p50 / max | 对比评测的 `max_steps`，看有没有回合超出评测时长 |
| 静止帧比例 | 平移+旋转动作的范数 < 阈值的帧占比，尤其是回合开头 | 遥操作数据常在开头有一段“没动”，模型会学到“发呆” |
| 夹爪动作分布 | 第 7 维的取值直方图、每回合开合次数 | 夹爪是二值动作，被 MEAN_STD 归一化后会怎样？ |
| 动作/状态统计量 | 和 checkpoint 里 `policy_preprocessor*` 保存的统计量对比 | 训练和部署的归一化必须一致 |
| 异常回合 | 长度离群、动作越界、含 NaN | 数据清洗的依据 |

**提示**：用 `LeRobotDataset` 的元数据（`meta/episodes`、`meta/stats`）和 parquet 里的 `action` 列就够了，**不要解码视频**，几分钟就能跑完。

**你应该交付**：一个审计脚本、一个 json、2–3 张图（回合长度直方图、静止帧比例、夹爪分布），以及一段“发现了什么”的文字。

**检查点问题**：
1. 数据集里 spatial 的回合占多少比例？这对“只测 spatial”意味着什么？
2. 如果开头 15% 的帧是静止的，你会删掉吗？删掉会带来什么副作用？

**技能**：拿到任何机器人数据集，30 分钟内产出一份“数据体检报告”。这是数据工程岗面试里最好讲的部分。

### T4 正式微调（1:00 启动，后台跑）

```bash
STEPS=20000 BATCH=32 SAVE_FREQ=2500 scripts/train.sh
```

`SAVE_FREQ=2500` 会存 8 个 checkpoint，2.5k 步那个就是“微调前期”参照。每个 checkpoint 除了模型权重，还有 `training_state/`（优化器状态，比权重还大）。先用 `du -sh outputs/smolvla_libero_ft/checkpoints/*` 看实际大小；硬盘紧张的话，评测只需要 `pretrained_model/`，中间 checkpoint 的 `training_state/` 可以删掉（`last` 的要保留，断点续训要用）。最终画曲线只评 2.5k / 5k / 10k / 20k 四个点，其余 checkpoint 不评。

放在 tmux 里，然后去做别的事。每小时看一次 loss，能说清楚 loss 的大致走势。

**检查点问题**：
1. `--rename_map` 不加会怎样？（回看 README 的“训练和部署必须一致”。）
2. `scheduler_decay_steps` 为什么要等于 `STEPS`？

**技能**：长任务后台化 + 中间产物落盘，**训练和评测流水线并行**。

### T5（选做）数据配比实验（8:30 之后，看预算）★ 数据工程岗加分

**目标**：做一次数据为中心的对比实验，用数据说话。

用 T2 得到的 spatial 回合索引，只用 spatial 数据训练一个同样步数（或减半）的模型：

```bash
RUN=ft_spatial_only STEPS=10000 scripts/train.sh --dataset.episodes='[<T2 输出的索引列表>]'
```

然后在 `libero_spatial` 上和主模型对比；有余力再都测一下 `libero_object`（`SUITE=libero_object`），看“专精 vs 泛化”的取舍。

**注意**：只训练一部分回合时，归一化统计量是按全量数据算的还是按子集算的？去 LeRobot 源码里确认一下，并记录下来，这是一个真实的坑。

**技能**：设计“只改一个变量”的数据实验，并诚实解读（差距在置信区间以内就说“没有显著差异”）。

### T6 评测训练曲线（边训边评 + 训练后）

```bash
CKPTS="002500 005000 010000" EPISODES=5 scripts/eval_ckpts.sh
```

训练期间每出一个新 checkpoint 就重跑一次这条命令，已经评过的会自动跳过。中间 checkpoint 用 5 回合/任务省时间；最终 checkpoint 用 10 回合/任务：

```bash
EPISODES=10 scripts/eval.sh outputs/smolvla_libero_ft/checkpoints/last/pretrained_model ft_last_n50
```

**你应该看到**：成功率随步数上升然后变平；最后一个点和官方 checkpoint 相比在同一量级（具体差多少都可以，只要如实写）。

**检查点问题**：如果 10k 和 20k 的成功率差不多，下次你会怎么分配 GPU 时间？

### T7 动作块执行步数消融（核心“细节优化”）

官方模型在训练期间就能跑：

```bash
scripts/sweep_n_action_steps.sh
```

训练完后，在微调模型上只补测关键的几个点：

```bash
POLICY=outputs/smolvla_libero_ft/checkpoints/last/pretrained_model NAME=ft VALUES="5 10 25" scripts/sweep_n_action_steps.sh
```

**这就是你的“零训练成本优化”故事**：微调模型默认 n=50（执行完整个动作块才重新推理），把 n 调到最佳值后，成功率从 X% 升到 Y%。

**检查点问题**：
1. n 越小越好吗？n=1 的代价是什么？（和 T8 的延迟联系起来。）
2. 为什么官方 checkpoint 用 n=1，而 SmolVLA 论文强调动作块？

**技能**：**部署参数也是超参数**，要在闭环里扫，不能只看离线 loss。

### T8 推理延迟与部署约束（GPU 必须空闲时跑）

```bash
python scripts/bench_latency.py --policy outputs/smolvla_libero_ft/checkpoints/last/pretrained_model
```

**一定要等训练和评测全停了再测**，否则延迟数据被污染，这是最常见的测量错误。

再验证“加速后成功率不掉”：

```bash
NUM_STEPS=5 scripts/eval.sh outputs/smolvla_libero_ft/checkpoints/last/pretrained_model ft_last_steps5
```

（这条可以和其他评测并行，它测的是成功率，不是延迟。）

**你要算出的结论**：
- BF16 相对 FP32 加速 X 倍，5 步去噪再加速 Y 倍；
- p90 延迟 → 20Hz 控制下最小可行的 n（脚本已经算了）；
- 把这个 n 代入 T7 的曲线 → **“这张卡上部署能达到的成功率”**。这一句就是整个项目的总结。

**检查点问题**：为什么用 p90 而不是 p50 来定 n？真机上还要多算哪些延迟？（相机采集、预处理、通信。）

**技能**：把“模型多快”翻译成“机器人能不能用”，这是部署工程师和算法同学的分水岭。
